## Summary

JWT validation could fall back to a static PEM verifier when a JWKS key id was not resolved. In mixed static/JWKS configurations, this widened the blast radius of a leaked static private key.

## Affected Versions / Configurations

Tenants that configured both static PEM verification and JWKS resolution are potentially affected. See `../internal-audit/R3-affected.csv`.

## Impact

If a static PEM private key is compromised, an attacker can use a key id outside the configured JWKS set and still reach the static verifier. That can bypass intended key-id scoping for affected tenants.

## Workaround

Remove static PEM fallback where JWKS is configured, or rotate static PEM keys before enabling the fixed build.

## Fix

The WS-5 fix adds allowed algorithm controls and stricter key-id fallback behavior. Final release version, git sha, and flag timeline must be filled before publication.

## Upgrade Guide

Upgrade to the fixed gateway build, confirm unknown key ids are rejected unless explicitly allowed, and monitor fallback warnings during the warn-only period.
