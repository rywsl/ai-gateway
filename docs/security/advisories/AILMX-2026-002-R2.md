## Summary

HMAC request signatures were accepted based on a timestamp freshness window without a required nonce cache. A captured signed request could be replayed within the accepted window when replay checking was not enabled.

## Affected Versions / Configurations

Tenants or vendor integrations that require HMAC signatures but do not enforce `signature.replay_check` are affected. See `../internal-audit/R2-affected.csv`.

## Impact

An attacker who obtains a valid signed request can repeat that exact request while it remains inside the freshness window. The main impact is unauthorized repeated state change for endpoints protected only by request signing.

## Workaround

Enable `signature.replay_check = "nonce_redis"` where Redis is available and ensure clients send non-empty nonce headers. If a compatibility window is needed, follow `../warn-only-protocol.md`.

## Fix

The WS-5 fix adds local and Redis nonce replay check modes plus a 60s timestamp drift window. Final release version and git sha must be filled before publication.

## Upgrade Guide

Upgrade clients to send nonce headers for signed requests, then enable replay checking in gateway configuration.
