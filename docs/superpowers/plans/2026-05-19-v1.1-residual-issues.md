# v1.1 Residual Issues Fix Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix the 3 residual issues identified by the 2026-05-19 warm-path final review:
1. StreamConsumer XREADGROUP parse error on empty replies (log spam every 200 ms).
2. Cold-load chain has no timeout — a stalled Postgres blocks every cache miss indefinitely.
3. `upstream_peer` / `rewrite_request` short-circuits return empty-body 500 instead of a vendor-flavoured JSON envelope.

**Architecture:**
1. Replace `xreadgroup_map` (which fails on `RESP::Null` empty replies) with `xreadgroup` returning a raw `RedisValue`; early-return on `Null` / empty arrays before invoking the map decoder. Eliminates the warn spam without touching observable behaviour.
2. Wrap each `load_<entity>` call inside `EntityStore::*_or_load` with `tokio::time::timeout(cold_load_timeout, ...)`. On timeout, the method returns `None` (matching the existing "missing entity" semantic) and increments a `gateway_cold_load_timeout_total{ns}` counter so operators can scrape for trouble. Timeout is configurable via `Config::loader::cold_load_timeout_ms` (default 2000).
3. Add a `short_circuit_with_envelope` helper in `gw-proxy` that pairs `error_emit::send_error` with `short_circuit(status)` (mirroring `emit_and_bail` in `filters/request.rs`). Migrate the four user-visible failure points in `filters/upstream.rs` (`gw_no_model_group`, `gw_model_group_missing`, `gw_routing_no_available_channel`, `gw_vendor_missing`) to emit a JSON envelope before returning `Err`. Internal sanity-check failures (`gw_no_model_in_ctx`, `gw_no_perm_in_ctx`, ...) stay as plain `Custom` errors — they signal a programmer bug and should keep the empty-body 500 so logs surface the underlying defect.

**Tech Stack:** Rust 1.86, `fred 9.4`, `tokio 1.x` (`time::timeout`), `moka 0.12`, pingora 0.8, existing `gw-codec` / `error_emit` infrastructure.

### Step 1.3 — Switch to raw `xreadgroup` + null-guard

The current code calls `xreadgroup_map` which invokes `into_xread_response()` → `flatten_array_values(2).convert()` → `from_value` for `HashMap<String, ...>`. When the underlying RESP reply is `Null` (the redis-side semantic for "block timeout, no messages"), the `from_value` lookup throws `Cannot convert to map`. Switching to the raw `xreadgroup` lets us inspect the raw `RedisValue` and short-circuit on Null before attempting the decode.

- [ ] **Edit `crates/gw-store/src/stream_consumer.rs`:** replace the `consume_loop` body.

Replace the existing imports block (`use fred::interfaces::StreamsInterface;` + `use fred::types::XReadResponse;`) with:

```rust

```

Replace the body of `consume_loop` (from the `loop {` line through the closing `}`) with:

```rust
async fn consume_loop(&self) {
    let consumer_name = format!("{}-consumer", self.instance_id);
    loop {
        let client = self.redis.pool.next();
        // We use the raw `xreadgroup` (returning RedisValue) instead of
        // `xreadgroup_map` because the latter's into_xread_response decoder
        // does not tolerate RESP `Null` replies — which is what redis returns
        // when BLOCK_MS expires with no messages. By inspecting the raw value
        // we can short-circuit on Null/empty before invoking the map decoder.
        let raw: Result<RedisValue, _> = client
            .xreadgroup(
                &*self.instance_id,
                &consumer_name,
                Some(COUNT_PER_POLL),
                Some(BLOCK_MS),
                // noack=false: explicit XACK below confirms processing.
                false,
                vec![ENTITY_STREAM, COUNTER_STREAM],
                vec![">", ">"],
            )
            .await;

        let value = match raw {
            Ok(v) => v,
            Err(e) => {
                tracing::warn!(
                    target: "gw_store::stream_consumer",
                    error = %e,
                    "xreadgroup failed; backing off"
                );
                tokio::time::sleep(Duration::from_millis(500)).await;
                continue;
            }
        };

        // Null = BLOCK timed out with no messages. Empty array = same shape
        // in RESP2 some redis versions. Either way: nothing to do this tick.
        if value.is_null() {
            continue;
        }
        if let RedisValue::Array(ref a) = value {
            if a.is_empty() {
                continue;
            }
        }

        let entries: XReadResponse<String, String, String, String> =
            match value.into_xread_response() {
                Ok(m) => m,
                Err(e) => {
                    tracing::warn!(
                        target: "gw_store::stream_consumer",
                        error = %e,
                        "xreadgroup non-null reply failed to parse; backing off"
                    );
                    tokio::time::sleep(Duration::from_millis(500)).await;
                    continue;
                }
            };

        for (stream, stream_entries) in entries {
            for (entry_id, fields) in stream_entries {
                self.apply(&stream, &fields).await;
                let ack: Result<u64, _> = client
                    .xack(stream.as_str(), &*self.instance_id, entry_id.clone())
                    .await;
                if let Err(e) = ack {
                    tracing::warn!(
                        target: "gw_store::stream_consumer",
                        error = %e,
                        stream = %stream,
                        entry_id = %entry_id,
                        "xack failed; will be redelivered"
                    );
                }
            }
        }
    }
}
```

```rust
use std::time::Duration;
use tokio::time::timeout;

/// Cold-load timeout wrapper.
///
/// Wraps a loader future with `tokio::time::timeout(deadline, fut)`. On
/// timeout, increments `gateway_cold_load_timeout_total{ns}` and returns
/// `None`. On `Err(_)`, returns `None` and lets the loader's own
/// `tracing::warn` carry the underlying message. On `Ok(v)`, returns
/// `Some(v)`.
pub async fn with_cold_load_timeout<T>(
    ns: &'static str,
    deadline: Duration,
    fut: impl std::future::Future<Output = anyhow::Result<T>>,
) -> Option<T> {
    match timeout(deadline, fut).await {
        Ok(Ok(v)) => Some(v),
        Ok(Err(e)) => {
            tracing::warn!(
                target: "gw_store::loader",
                ns = %ns,
                error = %e,
                "cold loader returned error"
            );
            None
        }
        Err(_elapsed) => {
            metrics::counter!(
                "gateway_cold_load_timeout_total",
                "ns" => ns,
            )
            .increment(1);
            tracing::warn!(
                target: "gw_store::loader",
                ns = %ns,
                deadline_ms = deadline.as_millis() as u64,
                "cold loader timed out"
            );
            None
        }
    }
}
```

Wrap each of the 8 `*_or_load` cold-load paths in `with_cold_load_timeout(...)`. Pattern (apply to all 8 methods):

```rust
pub async fn user_or_load(&self, id: &UserId) -> Option<Arc<Versioned<UserEntry>>> {
    if let Some(hit) = self.user.get(id).await {
        return Some(hit);
    }
    let loader = self.loader.as_ref()?.clone();
    let id2 = id.clone();
    let deadline = self.cold_load_timeout;
    self.user
        .try_get_with_by_ref(id, async move {
            with_cold_load_timeout("user", deadline, async move {
                load_user(&loader, &id2).await
            })
            .await
            .map(Arc::new)
            .ok_or_else(|| anyhow::anyhow!("cold-load timed out or failed"))
        })
        .await
        .ok()
}
```

Note the `.ok_or_else(|| anyhow::anyhow!(...))` is required because `try_get_with_by_ref` expects `Result<V, E>`; mapping `None` to `Err` causes Moka to NOT cache the failure (it only caches `Ok`), which is exactly what we want — a transient timeout shouldn't poison the entry.

Apply the same pattern to `user_group_or_load`, `apikey_or_load`, `vendor_or_load`, `vendor_key_or_load`, `model_group_or_load`, `pricing_or_load`, `jwks_or_load`, threading the appropriate namespace string (`"user_group"`, `"apikey"`, ...) and the matching `load_<entity>` function.

```rust
/// Build an `ErrorIR` for an upstream-filter short-circuit.
///
/// Categories chosen so the wire status + `Retry-After` headers reflect the
/// failure shape clients should react to:
/// - `GW_BACKEND_UNAVAILABLE` (no model_group / vendor configured) → 503
///   `UpstreamError`, retryable after 5 s once an operator seeds config.
/// - `GW_ROUTING_NO_AVAILABLE_CHANNEL` (all candidates filtered out) → 503,
///   retryable after 5 s once breakers close or capacity frees.
pub fn envelope_for(code: &'static str, message: &'static str, status: u16) -> ErrorIR<'static> {
    let category = match status {
        400..=499 => ErrorCategory::ClientBadRequest,
        500..=599 => ErrorCategory::UpstreamError,
        _ => ErrorCategory::GatewayInternal,
    };
    let retryable = matches!(status, 502 | 503 | 504 | 429);
    let retry_after_secs = if retryable { Some(5) } else { None };
    ErrorIR {
        category,
        status,
        upstream_status: None,
        code: Cow::Borrowed(code),
        message: Cow::Borrowed(message),
        retryable,
        upstream_raw: None,
        request_id: "",
        retry_after_secs,
    }
}

/// Render an envelope to the client via the client codec, then return a
/// short-circuit `Err` for pingora.
async fn emit_envelope_and_bail<T>(
    session: &mut Session,
    ctx: &ReqCtx,
    err: ErrorIR<'static>,
) -> Result<T> {
    let codec = pick_emit_codec(&ctx.client_codec);
    let scoped = with_request_id(&err, &ctx.request_id.0);
    error_emit::send_error(session, &codec, &scoped).await;
    Err(short_circuit(err.status))
}
```

## Risks and Mitigations

- **Risk:** fred 9.4's `xreadgroup` raw signature may differ across versions. **Mitigation:** Task 1 inspects `~/.cargo/registry/src/.../fred-9.4.0/src/commands/interfaces/streams.rs` to confirm the exact shape before editing; the test asserts the behavioural contract (zero warns on empty poll), so signature drift surfaces as a compile error rather than a runtime regression.
- **Risk:** `with_cold_load_timeout` wraps every cold-load including the write-back step, so a slow Redis write-back can also trigger the timeout. **Mitigation:** Acceptable — write-back failure is already silenced (`let _: Result<(), _> = client.hset(...).await;`), so timing it out is consistent. If write-backs dominate the timeout budget under load, v1.2 should split the deadline into "read deadline" vs "write-back deadline".
- **Risk:** Renaming `_session` → `session` in `pick_peer` may flag an "unused variable" warning if the smoke run path goes through the happy-path branches. **Mitigation:** Once the 4 envelope emits land, `session` is genuinely used; compiler is happy.
- **Risk:** The `envelope_for` heuristic `matches!(status, 502 | 503 | 504 | 429)` for `retryable` is coarse. **Mitigation:** Sufficient for v1.1 — clients use the explicit `Retry-After` header. v1.2 can introduce a per-code retryability map.
