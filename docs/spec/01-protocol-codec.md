# 01 — Protocol & Codec (as-built)
- Family: S (codec) · Backing crates: gw-codec, gw-codec-macros · Source-of-truth: `crates/gw-codec/src/any.rs`, `crates/gw-codec/src/cross_render.rs`, `crates/gw-codec/src/cli/mod.rs`, `crates/gw-core/src/protocol.rs` · Status: five standard wire shapes plus five registered CLI shapes; same-protocol passthrough zero-copy, cross-protocol re-render for both stream and non-stream paths.

## Purpose

The codec layer is the boundary between client wire traffic and the gateway's in-memory IR. It detects which API surface a client request speaks, parses requests/responses/stream chunks into IR, and renders IR back out through the matching (or a different) client codec. Five standard wire shapes are modelled as `AnyCodec` enum variants; registered CLI shapes run as a parallel body-passthrough module. When client and upstream speak the same protocol and the IR is unmutated, the request body is forwarded verbatim; when they differ, the response is re-rendered into the client's wire form with vendor-specific fields dropped per a capability table.

## As-built surface

**`AnyCodec` enum dispatcher** (`crates/gw-codec/src/any.rs`). Five variants: `OpenAi(OpenAi)`, `OpenAiResponses(OpenAiResponsesCodec)`, `Anthropic(Anthropic)`, `Gemini(Gemini)`, `Kiro(Kiro)`. `AnyCodec::detect(path, headers, body_head)` tries each protocol's `detect_request` in declaration order — Responses (`/v1/responses`) is checked before Chat (`/v1/chat/completions`) so the two OpenAI surfaces don't collide; Kiro EventStream detection is limited to `content-type: application/vnd.amazon.eventstream` plus a `/kiro` or `/s5` path and does not rely on the body prefix in the early path. `kind()` returns a `ProtocolKind` (both OpenAI variants collapse to `ProtocolKind::OpenAi`); `api_shape()` preserves finer shapes including `ApiShape::KiroEventStream`. The enum forwards `parse_request`, `render_request`, `parse_response`, `render_response`, `new_stream_state`, `parse_stream_chunk`, `render_stream_chunk`, `parse_error`, `render_error`, `estimate_input_tokens`, `path_implies_stream`, and `extract_path_model` to the concrete codec. `AnyCodec` itself does not implement `ProtocolCodec` (the trait's `detect_request` requires `Self: Sized`); `as_dyn()` borrows the underlying concrete codec as `&dyn ProtocolCodec` for callers such as cross-render. The concrete `detect_request` impls live in `crates/gw-codec/src/{openai,anthropic,gemini}/codec.rs`, `crates/gw-codec/src/openai/responses/codec.rs`, and `crates/gw-codec/src/kiro/mod.rs`.

**Same-protocol passthrough** (`crates/gw-codec/src/passthrough.rs`). `same_protocol_passthrough(codec, body, mutations)` returns `Cow::Borrowed(body)` (zero parse / serialize / copy) when `mutations.is_empty()`; otherwise it parses the body to IR and re-renders through the same codec, returning `Cow::Owned`. This is the path that carries a model rewrite or any other IR mutation.

**Cross-protocol render** (`crates/gw-codec/src/cross_render.rs`). `WireFormat` enumerates the five wire forms (`OpenAiChat`, `OpenAiResponses`, `AnthropicMessages`, `GeminiGenerate`, `KiroEventStream`); `WireFormat::from_any_codec` maps an `AnyCodec` variant 1:1 to a `WireFormat`. `WireFormat::capabilities()` returns a `WireCapabilities` struct of ~23 `supports_*` flags per wire form. Kiro EventStream advertises thinking support and otherwise only the fields its minimal frame renderer can represent. `CrossRender { from, to, source }::run(target_codec, buf)` calls `adapt_lossy()` then `target_codec.render_response`. `adapt_lossy()` strips IR fields the target wire cannot express (`thinking`, `reasoning`, `refusal`, `annotations`, `server_tool_blocks`, `redacted_thinking`, `service_tier`, `openai_audio` extension, and a set of `usage.*` sub-fields), each drop routed through `LossyField::drop(from, to, field)` which logs an `error!` and increments `gw_codec_cross_render_lossy_total{from,to,field}`. `map_finish_reason(from, to, fr)` maps finish reasons across wires: `Stop`/`Length`/`ToolCalls` pass through, `Refusal` degrades to `Stop` when the target lacks refusal support, `ContentFilter` degrades to `Stop` for Anthropic, and Gemini-specific `Other` values (`BLOCKLIST`, `PROHIBITED_CONTENT`, `SPII`, `MODEL_ARMOR`) map to content-filter while other `Other` values degrade to `Stop`. `tool_use_blocks` and flat `tool_calls` are treated as two wire forms of the same information and are not pre-stripped (the codec selects at render time by target capability).

**Cross-render and CLI usage metrics** (`crates/gw-proxy/src/filters/response.rs`, `crates/gw-gateway/src/metrics_catalog.rs`). Streaming cross-render re-renders each IR event through the client codec into a shared accumulator and increments `gw_codec_cross_render_total{from,to}` (labels are `ProtocolKind::as_str()`); the same-protocol branch increments `gw_codec_passthrough_total`. Non-stream cross-render (response filter, `WireFormat::from_any_codec` for `from`/`to`, guarded by `from != to`) runs `CrossRender::run` and increments `gw_codec_cross_render_nonstream_total{from,to}` on success or `gw_codec_cross_render_nonstream_failure_total{from,to}` on render failure (it then falls back to forwarding the original upstream bytes). Usage extraction is decoupled from re-render so usage is still recorded when re-render fails. CLI usage extraction increments `gw_cli_usage_extract_total{shape,source}` where `shape` is `ApiShape::format_id()` and `source` is `stream_event` or `response_body`.

**SSE/EventStream accumulators** (one per shape). `OpenAiStreamState` (`crates/gw-codec/src/openai/state.rs`) keys open tool-calls by the per-chunk integer `index`, emitting `ToolCallStart` once and `ToolCallDelta` per fragment. `AnthropicStreamState` (`crates/gw-codec/src/anthropic/state.rs`) keys `open_blocks` by `content_block_index` (text / thinking / tool_use), captures `seen_message_id`, and assigns a monotonic `next_tool_call_index` because Anthropic does not number tool_use blocks on the wire. `GeminiStreamState` (`crates/gw-codec/src/gemini/state.rs`) tracks `pending_function_calls` in arrival order (slot position is the IR index; Gemini tool calls have no upstream id, so the IR `id` is empty). `OpenAiResponsesStreamState` (`crates/gw-codec/src/openai/responses/state.rs`) keys `pending_reasoning` and `pending_function_calls` by stable string `item_id`, buffers reasoning summary fragments into a `ReasoningBuilder` emitted as a single `ThinkingDelta`, and assigns `next_tool_call_index`. Kiro EventStream currently uses an empty stream state and maps each complete AWS EventStream frame payload into text deltas and `<thinking>` sections. The Anthropic tool-call block mapping (tool_use blocks ↔ flat `tool_calls` ↔ Anthropic-shape `tool_use_blocks`) lives in `crates/gw-codec/src/anthropic/via.rs` (`render_assistant_blocks`, the request-side and response-side block walkers).

**CLI shapes** (`crates/gw-core/src/protocol.rs`, `crates/gw-codec/src/cli/`). `ApiShape` (`crates/gw-core/src/protocol.rs`) carries five standard surfaces plus five registered CLI variants: `ClaudeCli`, `OpenAiCli`, `OpenAiCompact`, `GeminiCli`, `KiroCli`. `ApiShape::format_id()` yields Aether-compatible strings (`claude:cli`, `openai:cli`, `openai:compact`, `gemini:cli`, `kiro:cli`, etc.); `is_cli()` is true for CLI variants and false for `KiroEventStream`; `protocol_kind()` folds each shape to its vendor `ProtocolKind`. `detect_cli(path, headers)` (`crates/gw-codec/src/cli/mod.rs`) returns an `ApiShape`: `/v1/responses/compact` → `OpenAiCompact`, `/v1/responses` → `OpenAiCli`, `/v1/messages` with a bearer token and no `x-api-key` → `ClaudeCli`, and a Gemini path (`/v1beta/models/` or `/v1/models/`) with a CLI `x-app`/`user-agent` header → `GeminiCli`. Kiro CLI marker detection, usage extraction, and passthrough behavior are not implemented; `KiroCli` is registered so cross-process shape contracts can distinguish it from `KiroEventStream`. The `CliCodec` trait (`crates/gw-codec/src/cli/mod.rs`) exposes `shape`, default-zero-copy `passthrough_request`/`passthrough_response_chunk`, `extract_hints`, `usage_extractor`, and `ttft_event_types`. Implemented concrete codecs live in `crates/gw-codec/src/cli/claude_cli.rs`, `openai_cli.rs`, `openai_compact.rs` (compact strips an SSE `data:` prefix before parsing usage), `gemini_cli.rs` (extracts model from the path and stream-ness from `:streamGenerateContent`). Per-shape usage extractors implement `CliUsageExtractor` (`crates/gw-codec/src/cli/traits.rs`) returning `CliUsageDelta` (stream) / `CliUsageFull` (non-stream); `CliHints` carries optional `model` and `stream`.

**CLI cross-protocol denial** (`crates/gw-proxy/src/filters/upstream.rs`). When `ctx.client_shape` is a CLI shape, candidate vendor keys are retained only if their `accessible_endpoints` contain the CLI shape's vendor `ProtocolKind`. If none qualify, the filter increments `gw_cli_cross_protocol_denied_total{client_shape,required_kind}` and bails with error code `GW_REQUEST_CLI_NO_SAME_PROTOCOL_CHANNEL` (`crates/gw-core/src/error/codes.rs`, HTTP 503). CLI requests therefore require a same-protocol upstream channel.

**Upstream format resolution** (`crates/gw-core/src/protocol.rs`). `resolve_upstream_format(accessible, client)` is the single source of truth for client→upstream codec selection: client format if accessible (same-protocol passthrough), else the first accessible endpoint, else `client` as a deferred error the call site re-checks via `accessible.is_empty()`.

## Deliberate behaviours

- **Responses-before-Chat detect order** (`crates/gw-codec/src/any.rs`): `OpenAiResponsesCodec::detect_request` is tried before `OpenAi::detect_request` so `/v1/responses` is not swallowed by the Chat path.
- **`AnyCodec` does not implement `ProtocolCodec`** (`crates/gw-codec/src/any.rs`): the trait's `detect_request` requires `Self: Sized`, which the enum dispatcher cannot satisfy; `as_dyn()` is the trait-object escape hatch.
- **Lossy drops are surfaced, not silent** (`crates/gw-codec/src/cross_render.rs`): every cross-render field strip logs at `error` level and increments `gw_codec_cross_render_lossy_total`; this is expected during legitimate cross-protocol conversions, not necessarily a fault.
- **`finish_reason::Other` does not propagate its string downstream** (`crates/gw-codec/src/cross_render.rs`): unrecognised `Other` values degrade to `Stop` rather than carrying a vendor-specific string into a foreign wire.
- **CLI requires a same-protocol channel** (`crates/gw-proxy/src/filters/upstream.rs`): CLI shapes are body-passthrough with no IR conversion, so a cross-protocol upstream is rejected hard with `GW_REQUEST_CLI_NO_SAME_PROTOCOL_CHANNEL` rather than attempting a re-render.
- **Non-stream cross-render failure forwards original bytes** (`crates/gw-proxy/src/filters/response.rs`): on render failure the gateway returns the upstream body verbatim (matching same-protocol fallback) and still records usage.
- **Gemini tool calls carry an empty IR id** (`crates/gw-codec/src/gemini/state.rs`): Gemini parts have no upstream id, so the IR `id` is the empty string by design.

## Cross-process touchpoints

The codec layer's CLI usage extractors and IR usage accumulation feed the usage figures that the proxy writes to the Redis `usage:records` stream consumed by the Go billing service; the codec itself computes no cost. `ApiShape::format_id()` produces the Aether-compatible `FORMAT_ID` strings (`openai:chat`, `anthropic:messages`, `claude:cli`, …) used in those cross-process payloads. See `docs/go-contracts/main.md` for the stream payload contract.

## Invariants & lints

- `no_cost_micro` / `no_billing_crate` (`scripts/check-invariants.sh`): the codec computes usage tokens but never cost — cost is the Go billing service's job.
- `no_v1_markers_in_prod` (`scripts/check-invariants.sh`, error mode): codec production code is free of panic-placeholder and version-marker stubs.
- Metric names are registered in the catalog (`crates/gw-gateway/src/metrics_catalog.rs`): `gw_codec_cross_render_total`, `gw_codec_cross_render_nonstream_total`, `gw_cli_cross_protocol_denied_total`, `gw_cli_usage_extract_total` all have catalog entries; `gw_codec_cross_render_lossy_total` is emitted from `crates/gw-codec/src/cross_render.rs`.

## Not built → ROADMAP

- **Kiro vendor integration** — Kiro EventStream is registered as `AnyCodec::Kiro`, `ProtocolKind::Kiro`, and `ApiShape::KiroEventStream`, but AWS SigV4, vendor auth injection, and full Kiro upstream adapter integration remain pending.
- **Kiro CLI behavior** — `ApiShape::KiroCli` is registered for cross-process shape compatibility, but marker detection, usage extraction, and passthrough semantics remain in the W7/Kiro CLI lane. Until then, Kiro CLI usage helpers fail closed with no extracted usage.
- **CLI as `AnyCodec` variants** — CLI shapes live as a parallel `crates/gw-codec/src/cli/` module (body passthrough), not as variants of the `AnyCodec` enum.
