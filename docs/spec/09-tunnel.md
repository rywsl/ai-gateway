# 09 — Tunnel (as-built)
- Family: tunnel · Backing crate: gw-tunnel-client · Source-of-truth: `crates/gw-tunnel-client/src/{frame,transport,pool,resolver,safe_dns,target_filter}.rs`, `crates/gw-proxy/src/tunnel_stack.rs`, `crates/gw-proxy/src/filters/upstream.rs` (cfg-gated blocks) · Status: WS frame codec/transport primitives, node resolution, safe DNS, target filtering, config boot, and split CI artifacts exist behind `--features tunnel`; the production HTTP<->WS frame stream bridge is not built. CI builds both a default non-tunnel image and a tunnel-enabled `*-tunnel` / `latest-tunnel` image; Cargo defaults remain `default = []`, and runtime enablement still requires `[tunnel].enabled = true`.

## Purpose
Prepare selected upstream LLM traffic to route through a remote WebSocket proxy node ("aether-hub" frame protocol) instead of dialing the provider directly, so egress can originate from a different network location once the runtime bridge exists. The decision is per-`VendorKey`: the resolver picks a node (or Direct) from the key's `tunnel_preference` and the operator-configured node list, `TunnelStack::peer_for_node` materialises a Pingora `HttpPeer` whose socket terminates at the node's WS endpoint, and SSRF/whitelist guards bound what the node may be asked to reach. The transport primitives can carry the real upstream target inside an `Open` frame, but the production Pingora HTTP request/response stream is not currently bridged into `Open`/`Data` frames.

## As-built surface
- Frame codec — `crates/gw-tunnel-client/src/frame.rs`: `Frame { msg_type, flags, stream_id, payload }`; `MsgType` (`Open=0x01 … Pong=0x05`, `Error=0x06`, `ControlAuth=0x10`, `ControlNodeInfo=0x11`); `encode_frame` / `decode_frame`; constants `MAGIC=[0xAE,0x21]`, `VERSION=1`, `HEADER_LEN=14`, `MAX_PAYLOAD_LEN=4 MiB`; `FrameError` (BadMagic / BadVersion / UnknownMsgType / PayloadTooLarge). Header layout `magic(2)|version(1)|msg_type(1)|flags(2)|stream_id(4)|length(4)|payload`.
- WS transport — `crates/gw-tunnel-client/src/transport.rs`: `WsTransport::connect` (tokio-tungstenite) spawns three tasks (send loop, recv/pong-tracking loop, heartbeat loop); `TransportConfig { url, auth_token, heartbeat_interval=30s, missed_pong_threshold=3, max_streams_per_conn=256 }`; when `auth_token` is present it sends a `ControlAuth` frame on stream `0` after the WS split is ready; `is_alive`, `last_pong_age`, `send_open(target) -> stream_id`, `send_data(stream_id, payload)`. `send_open` and `send_data` are transport primitives only: no production caller currently converts a Pingora upstream HTTP stream into those frames. Liveness is an `AtomicBool` flipped on send error, stream error, or missed-pong threshold.
- Reconnect pool — `crates/gw-tunnel-client/src/pool.rs`: `PoolConfig { heartbeat_interval, max_streams_per_conn, backoff_min=1s, backoff_max=60s, backoff_jitter=0.2 }`; `jittered_backoff(attempt, cfg)` = `min*2^attempt` capped at `max` then perturbed `±jitter`; `ReconnectingTransport::start` supervises a `WsTransport` behind an `ArcSwapOption`, recreating it on death with backoff; `current()` returns the live handle or `None` between attempts.
- Resolver — `crates/gw-tunnel-client/src/resolver.rs`: `resolve_tunnel(ctx, nodes) -> TunnelResolution::{Use(node_id), Direct}`. Filters nodes by `enabled`, `allowed_provider_ids` containing the provider, and `allowed_vendor_key_ids` (empty = unrestricted); intersects with `preference.preferred_node_ids` when non-empty; empty result ⇒ `Direct`; sorts by `latency_ms` when `prefer_low_latency`. Re-exports `gw_core::entity::TunnelPreference` as `TunnelPreference`. `ProxyNodeView` mirrors the entity (`id, ws_url, auth_token, enabled, latency_ms, allowed_provider_ids, allowed_vendor_key_ids`).
- Safe DNS — `crates/gw-tunnel-client/src/safe_dns.rs`: `is_ip_blocked` (private/loopback/link-local/broadcast/documentation/unspecified/CGNAT 100.64/8 for v4; loopback/unspecified/ULA fc00::/7/link-local fe80::/10 for v6); `BlockedIpError`; `SafeDnsResolver::cloudflare_default()` (hickory DoH over Cloudflare HTTPS) with a TTL+capacity LRU cache (`cache_ttl=600s`, `cache_cap=4096`); `resolve` order = override map → cache → DoH, post-filtering every IP through `is_ip_blocked` and returning `Err` on any blocked IP (no fall-through to another IP); `set_override` + `OverrideGuard` (test-only override/restore).
- Target whitelist — `crates/gw-tunnel-client/src/target_filter.rs`: process-global, default-deny `(host, port)` whitelist (`ArcSwap`); `set_whitelist`, `assert_target_allowed(url) -> Result<(), TargetDenied>` (ticks `gw_target_filter_denied_total`), `ResetGuard` for tests.
- Decision stack — `crates/gw-proxy/src/tunnel_stack.rs`: `TunnelStack` owns a `DashMap<node_id, Arc<ReconnectingTransport>>` (created lazily), an `ArcSwap<Vec<ProxyNodeView>>`, an `Arc<SafeDnsResolver>`, the `PoolConfig`, and a `TransportConfig` template. `resolve(provider_id, key_id, pref)` delegates to `resolve_tunnel` over the live snapshot. `peer_for_node(node_id, host, port)` pre-resolves the upstream host through `SafeDnsResolver` (`DnsBlocked` on blocked/private IP), takes one node snapshot, lazily spawns the node's `ReconnectingTransport` with the node `auth_token`, returns `TunnelPeerError::NoLive` when `current()` is `None`, runs the upstream `host:port` through `assert_target_allowed` (`TargetDenied` on reject), and otherwise builds an `HttpPeer` pointed at the node's `ws_url` (TLS when scheme is `wss`). It does not call `WsTransport::send_open`, so the target validation currently precedes a node `HttpPeer` choice rather than a complete frame relay. `reload_nodes` wholesale-swaps the snapshot; `start_probe_loop(interval)` emits `gw_tunnel_transport_present` and `gw_tunnel_last_pong_age_seconds`; `health_snapshot()` feeds the tunnel health endpoint with `transport_present` and live `last_pong_age_secs`.
- Upstream wiring (feature-gated) — `crates/gw-proxy/src/filters/upstream.rs`: under `#[cfg(feature = "tunnel")]` the filter resolves `(tunnel_resolution, tunnel_require)` once from `picked_arc.tunnel_preference` (defaulting to `TunnelPreference::default()`) by calling `TunnelStack::resolve`; the impersonate branch bails with `GW_TUNNEL_IMPERSONATE_CONFLICT` (503) if resolution is `Use(_)`; the rustls branch maps `Direct`+`require_tunnel` → `GW_TUNNEL_NO_NODE` (502), `Direct` → Direct `HttpPeer`, `Use(node_id)` → `peer_for_node` (errors mapped to `GW_TUNNEL_NO_LIVE` 502 / `GW_TUNNEL_DNS_BLOCKED` 502 / `GW_TUNNEL_TARGET_DENIED` 502); `gw_tunnel_resolve_total{result=...}` ticks per outcome and `ctx.tunnel_resolution` records the chosen path. This is decision/peer wiring, not a full upstream body relay. Under `#[cfg(not(feature = "tunnel"))]`, `default_build_requires_tunnel` still rejects `VendorKey.tunnel_preference.require_tunnel = true` with `GW_TUNNEL_NO_NODE`; otherwise it records `ctx.tunnel_resolution = Some("direct")` and builds a Direct `HttpPeer`.
- Entities — `crates/gw-core/src/entity.rs`: `TunnelPreference { preferred_node_ids, require_tunnel, prefer_low_latency }` (lives in `gw-core` because `VendorKey` embeds it; line 460); `VendorKey.tunnel_preference: Option<TunnelPreference>` (line 215); `ProxyNode { id, ws_url, enabled, latency_ms, allowed_provider_ids, allowed_vendor_key_ids, auth_token_enc }` (line 501).
- Error codes — `crates/gw-core/src/error/codes.rs`: `GW_TUNNEL_NO_NODE`, `GW_TUNNEL_NO_LIVE`, `GW_TUNNEL_TARGET_DENIED`, `GW_TUNNEL_DNS_BLOCKED`, `GW_TUNNEL_IMPERSONATE_CONFLICT` (lines 106–112).
- Boot wiring (feature-gated) — `crates/gw-gateway/src/lib.rs`: `pub use gw_tunnel_client` (line 45); when `cfg.tunnel.enabled` is true (line 728) the boot path parses `tunnel.target_whitelist` into `set_whitelist`, builds `PoolConfig`/`TransportConfig`/`SafeDnsResolver::cloudflare_default()`, decrypts `ProxyNode.auth_token_enc` into `ProxyNodeView.auth_token`, loads `proxy_nodes_list_or_load()` into `ProxyNodeView`s, constructs the `TunnelStack`, spawns a 5s polling node-refresh task, and calls `start_probe_loop`; nodes with undecryptable auth tokens are dropped during refresh. When false it logs and yields `None`. Config struct keys come from `config/default.toml` `[tunnel]` (`enabled=false`, `doh="cloudflare"`, `dns_cache_ttl_secs=600`, `target_whitelist=[]`, `heartbeat_interval_secs=30`, `missed_pong_threshold=3`, `backoff_min_secs=1`, `backoff_max_secs=60`, `max_streams_per_conn=256`).
- Feature flags — `crates/gw-proxy/Cargo.toml`: `default = []`, `tunnel = ["dep:gw-tunnel-client"]`. `crates/gw-gateway/Cargo.toml`: `default = []`, `tunnel = ["dep:gw-tunnel-client", "gw-proxy/tunnel"]`.
- CI artifacts — `.gitlab-ci.yml`: `rust-build` / `push-image` build the default non-tunnel artifact and tag `latest`; `rust-build-tunnel` / `push-tunnel-image` build with `--features tunnel` and tag `latest-tunnel`. `Dockerfile` accepts `ARG CARGO_FEATURES` and passes it to `cargo build`.

## Deliberate behaviours
- Tunnel data path is opt-in twice over: it requires both the `tunnel` Cargo feature at build time and `cfg.tunnel.enabled = true` at boot. With either off and no key requiring a tunnel, `pick_peer` sees `tunnel = None` (or the `not(feature)` arm) and produces a byte-identical Direct `HttpPeer` — the comments in `crates/gw-proxy/src/filters/upstream.rs` and `crates/gw-gateway/src/lib.rs` call this the non-breaking-on-rollout guarantee.
- `require_tunnel = true` is a hard constraint in both feature builds and default builds: when resolution is `Direct`, or when the binary is compiled without `feature = "tunnel"`, `crates/gw-proxy/src/filters/upstream.rs` returns `GW_TUNNEL_NO_NODE` rather than falling back to Direct (ADR-T-4, enforced by the `tunnel_require_means_hard_fail` invariant).
- Tunnel and impersonate are mutually exclusive: a vendor whose `egress_mode = Impersonate` that also resolves to `Use(_)` is failed with `GW_TUNNEL_IMPERSONATE_CONFLICT` (503) instead of silently picking one path (`crates/gw-proxy/src/filters/upstream.rs`).
- Anti-SSRF is fail-closed: `SafeDnsResolver::resolve` returns `BlockedIpError` if any resolved IP is in the blocklist and does not try a different IP (`crates/gw-tunnel-client/src/safe_dns.rs`); `assert_target_allowed` defaults to deny and only permits explicit `(host, port)` pairs (`crates/gw-tunnel-client/src/target_filter.rs`).
- Cold-start nodes fail soft into retry: `peer_for_node` returns `NoLive` when a freshly-spawned transport has not completed its handshake; the rustls branch pushes the key onto `ctx.retry_blacklist` before emitting `GW_TUNNEL_NO_LIVE`, so a request retry lands on a different key (`crates/gw-proxy/src/filters/upstream.rs`, `crates/gw-proxy/src/tunnel_stack.rs`).
- Decode is memory-bounded: frames whose declared length exceeds `MAX_PAYLOAD_LEN` are rejected at decode (`crates/gw-tunnel-client/src/frame.rs`).
- Node list reloads are atomic: `peer_for_node` takes one `nodes.load_full()` snapshot for the whole method so a concurrent `reload_nodes` cannot make its two node-lookup sites disagree (`crates/gw-proxy/src/tunnel_stack.rs`).
- Split artifacts are the documented operator model for now: default `latest` is non-tunnel, and `latest-tunnel` is the operator-selected tunnel build. Making the default artifact tunnel-enabled would change rollout blast radius and needs a release decision after the bridge and e2e loop are closed.

## Cross-process touchpoints
- Remote proxy node (aether-hub): the frame byte layout in `crates/gw-tunnel-client/src/frame.rs` is declared to match `aether-hub/src/protocol.rs`; `WsTransport` dials the node's `ws[s]://host:port/path` and can send the real upstream target as an `Open` frame payload. The production proxy path does not yet bridge Pingora HTTP traffic into that frame protocol.
- DoH provider: `SafeDnsResolver::cloudflare_default()` resolves over Cloudflare DoH (`1.1.1.1`/`1.0.0.1`) via hickory (`crates/gw-tunnel-client/src/safe_dns.rs`).
- Datastore: proxy nodes come from `EntityStore::proxy_nodes_list_or_load()` (migration `0005_proxy_nodes.sql`), mapped `ProxyNode → ProxyNodeView` at boot and on the 5s refresh poll (`crates/gw-gateway/src/lib.rs`); `VendorKey.tunnel_preference` rides the vendor-key entity.
- Node auth: `ProxyNode.auth_token_enc` is decrypted by `crates/gw-gateway/src/lib.rs` with the gateway KEK and passed as `ProxyNodeView.auth_token`; `crates/gw-tunnel-client/src/transport.rs` sends it as a `ControlAuth` frame when present.
- Admin/health: `TunnelStack::health_snapshot()` and the `#[cfg(feature = "tunnel")]` block in `crates/gw-gateway/src/health.rs` expose per-node `transport_present` and `last_pong_age_seconds`.
- Metrics: `gw_tunnel_resolve_total`, `gw_tunnel_open_total`, `gw_tunnel_transport_present`, `gw_tunnel_last_pong_age_seconds`, `gw_tunnel_reconnect_total`, `gw_tunnel_doh_resolve_total`, `gw_target_filter_denied_total`.

## Invariants & lints
- `no_dead_tunnel_use_alias` (`scripts/check-invariants.sh`): the `pub use gw_tunnel_client` re-export count in `crates/gw-gateway/src/` and the `TunnelStack` mention count in `crates/gw-proxy/src/` must both be zero or both be nonzero — the re-export and the consumer move together.
- `tunnel_require_means_hard_fail` (`scripts/check-invariants.sh`): every `require_tunnel` source line in `crates/` must have a `GW_TUNNEL_NO_NODE` within the next 8 lines, forbidding a silent Direct fallback when a tunnel is required.
- `no_double_rustls` (`scripts/check-invariants.sh`): `Cargo.lock` may hold exactly one `rustls` version, so the tunnel WS TLS stack does not introduce a second rustls (the gateway already installs a single ring provider; see `crates/gw-gateway/Cargo.toml`).
- `crate_layering` (`scripts/check-invariants.sh`): `gw-tunnel-client` is business-layer and must not depend on the execution layer; `gw-capability` must not depend on `gw-tunnel-client`.

## Not built → ROADMAP
- **HTTP<->WS frame bridge runtime.** `WsTransport::send_open` / `send_data` exist, but no production caller maps Pingora upstream HTTP bytes into `Open` / `Data` frames or relays response frames back to the client. Full tunnel traffic needs that runtime bridge and a matching remote-node contract. (decision-gated residual)
- **Full round-trip e2e.** `crates/gw-gateway/tests/e2e_tunnel.rs` is `#![cfg(feature = "tunnel")]` and both `#[tokio::test]`s carry `#[ignore = "requires Docker (testcontainers Redis + Postgres); full pingora round-trip is v2 scope"]`; current coverage is storage/resolve-oriented and does not exercise a live WS node, Open frame forwarding, or response relay. (decision-gated residual)
- **Default artifact policy.** The documented split remains `latest` non-tunnel and `latest-tunnel` operator-selected. Changing default `latest` to include tunnel should wait for bridge/e2e closure and requires an explicit release decision. (decision-gated residual)
