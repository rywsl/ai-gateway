# 09 — Tunnel (as-built)
- Family: tunnel · Backing crate: gw-tunnel-client · Source-of-truth: `crates/gw-tunnel-client/src/{frame,transport,pool,resolver,safe_dns,target_filter}.rs`, `crates/gw-proxy/src/tunnel_stack.rs`, `crates/gw-proxy/src/filters/upstream.rs` (cfg-gated blocks) · Status: a full WS-frame relay client + decision stack exists, but is compiled out of the shipped binary — both `gw-proxy` and `gw-gateway` declare `default = []`, the GitLab release build does not pass `--features tunnel`, so only the `#[cfg(not(feature = "tunnel"))]` Direct arm is in the artifact.

## Purpose
Route selected upstream LLM traffic from the gateway through a remote WebSocket proxy node ("aether-hub" frame protocol) instead of dialing the provider directly, so egress can originate from a different network location. The decision is per-`VendorKey`: the resolver picks a node (or Direct) from the key's `tunnel_preference` and the operator-configured node list, the `TunnelStack` materialises a Pingora `HttpPeer` whose socket terminates at the node's WS endpoint, and SSRF/whitelist guards bound what the node may be asked to reach. The transport layer carries the real upstream target inside an `Open` frame; Pingora only sees the gateway-to-node connection.

## As-built surface
- Frame codec — `crates/gw-tunnel-client/src/frame.rs`: `Frame { msg_type, flags, stream_id, payload }`; `MsgType` (`Open=0x01 … Pong=0x05`, `Error=0x06`, `ControlAuth=0x10`, `ControlNodeInfo=0x11`); `encode_frame` / `decode_frame`; constants `MAGIC=[0xAE,0x21]`, `VERSION=1`, `HEADER_LEN=14`, `MAX_PAYLOAD_LEN=4 MiB`; `FrameError` (BadMagic / BadVersion / UnknownMsgType / PayloadTooLarge). Header layout `magic(2)|version(1)|msg_type(1)|flags(2)|stream_id(4)|length(4)|payload`.
- WS transport — `crates/gw-tunnel-client/src/transport.rs`: `WsTransport::connect` (tokio-tungstenite) spawns three tasks (send loop, recv/pong-tracking loop, heartbeat loop); `TransportConfig { url, heartbeat_interval=30s, missed_pong_threshold=3, max_streams_per_conn=256 }`; `is_alive`, `last_pong_age`, `send_open(target) -> stream_id`, `send_data(stream_id, payload)`. Liveness is an `AtomicBool` flipped on send error, stream error, or missed-pong threshold.
- Reconnect pool — `crates/gw-tunnel-client/src/pool.rs`: `PoolConfig { heartbeat_interval, max_streams_per_conn, backoff_min=1s, backoff_max=60s, backoff_jitter=0.2 }`; `jittered_backoff(attempt, cfg)` = `min*2^attempt` capped at `max` then perturbed `±jitter`; `ReconnectingTransport::start` supervises a `WsTransport` behind an `ArcSwapOption`, recreating it on death with backoff; `current()` returns the live handle or `None` between attempts.
- Resolver — `crates/gw-tunnel-client/src/resolver.rs`: `resolve_tunnel(ctx, nodes) -> TunnelResolution::{Use(node_id), Direct}`. Filters nodes by `enabled`, `allowed_provider_ids` containing the provider, and `allowed_vendor_key_ids` (empty = unrestricted); intersects with `preference.preferred_node_ids` when non-empty; empty result ⇒ `Direct`; sorts by `latency_ms` when `prefer_low_latency`. Re-exports `gw_core::entity::TunnelPreference` as `TunnelPreference`. `ProxyNodeView` mirrors the entity (`id, ws_url, enabled, latency_ms, allowed_provider_ids, allowed_vendor_key_ids`).
- Safe DNS — `crates/gw-tunnel-client/src/safe_dns.rs`: `is_ip_blocked` (private/loopback/link-local/broadcast/documentation/unspecified/CGNAT 100.64/8 for v4; loopback/unspecified/ULA fc00::/7/link-local fe80::/10 for v6); `BlockedIpError`; `SafeDnsResolver::cloudflare_default()` (hickory DoH over Cloudflare HTTPS) with a TTL+capacity LRU cache (`cache_ttl=600s`, `cache_cap=4096`); `resolve` order = override map → cache → DoH, post-filtering every IP through `is_ip_blocked` and returning `Err` on any blocked IP (no fall-through to another IP); `set_override` + `OverrideGuard` (test-only override/restore).
- Target whitelist — `crates/gw-tunnel-client/src/target_filter.rs`: process-global, default-deny `(host, port)` whitelist (`ArcSwap`); `set_whitelist`, `assert_target_allowed(url) -> Result<(), TargetDenied>` (ticks `gw_target_filter_denied_total`), `ResetGuard` for tests.
- Decision stack — `crates/gw-proxy/src/tunnel_stack.rs`: `TunnelStack` owns a `DashMap<node_id, Arc<ReconnectingTransport>>` (created lazily), an `ArcSwap<Vec<ProxyNodeView>>`, an `Arc<SafeDnsResolver>`, the `PoolConfig`, and a `TransportConfig` template. `resolve(provider_id, key_id, pref)` delegates to `resolve_tunnel` over the live snapshot. `peer_for_node(node_id, host, port)` takes one node snapshot, lazily spawns the node's `ReconnectingTransport`, returns `TunnelPeerError::NoLive` when `current()` is `None`, runs the upstream `host:port` through `assert_target_allowed` (`TargetDenied` on reject), and otherwise builds an `HttpPeer` pointed at the node's `ws_url` (TLS when scheme is `wss`). `reload_nodes` wholesale-swaps the snapshot; `start_probe_loop(interval)` emits `gw_tunnel_transport_present` gauges; `health_snapshot()` feeds the tunnel health endpoint (`last_pong_age_secs` is always `None`).
- Upstream wiring (feature-gated) — `crates/gw-proxy/src/filters/upstream.rs`: under `#[cfg(feature = "tunnel")]` the filter resolves `(tunnel_resolution, tunnel_require)` once from `picked_arc.tunnel_preference` (defaulting to `TunnelPreference::default()`) by calling `TunnelStack::resolve`; the impersonate branch bails with `GW_TUNNEL_IMPERSONATE_CONFLICT` (503) if resolution is `Use(_)`; the rustls branch maps `Direct`+`require_tunnel` → `GW_TUNNEL_NO_NODE` (502), `Direct` → Direct `HttpPeer`, `Use(node_id)` → `peer_for_node` (errors mapped to `GW_TUNNEL_NO_LIVE` 502 / `GW_TUNNEL_TARGET_DENIED` 502); `gw_tunnel_resolve_total{result=...}` ticks per outcome and `ctx.tunnel_resolution` records the chosen path. Under `#[cfg(not(feature = "tunnel"))]` the body is just `ctx.tunnel_resolution = Some("direct")` + a Direct `HttpPeer`.
- Entities — `crates/gw-core/src/entity.rs`: `TunnelPreference { preferred_node_ids, require_tunnel, prefer_low_latency }` (lives in `gw-core` because `VendorKey` embeds it; line 460); `VendorKey.tunnel_preference: Option<TunnelPreference>` (line 215); `ProxyNode { id, ws_url, enabled, latency_ms, allowed_provider_ids, allowed_vendor_key_ids, auth_token_enc }` (line 501).
- Error codes — `crates/gw-core/src/error/codes.rs`: `GW_TUNNEL_NO_NODE`, `GW_TUNNEL_NO_LIVE`, `GW_TUNNEL_TARGET_DENIED`, `GW_TUNNEL_DNS_BLOCKED`, `GW_TUNNEL_IMPERSONATE_CONFLICT` (lines 106–112).
- Boot wiring (feature-gated) — `crates/gw-gateway/src/lib.rs`: `pub use gw_tunnel_client` (line 45); when `cfg.tunnel.enabled` is true (line 692) the boot path parses `tunnel.target_whitelist` into `set_whitelist`, builds `PoolConfig`/`TransportConfig`/`SafeDnsResolver::cloudflare_default()`, loads `proxy_nodes_list_or_load()` into `ProxyNodeView`s, constructs the `TunnelStack`, spawns a 5s polling node-refresh task, and calls `start_probe_loop`; when false it logs and yields `None`. Config struct keys come from `config/default.toml` `[tunnel]` (`enabled=false`, `doh="cloudflare"`, `dns_cache_ttl_secs=600`, `target_whitelist=[]`, `heartbeat_interval_secs=30`, `missed_pong_threshold=3`, `backoff_min_secs=1`, `backoff_max_secs=60`, `max_streams_per_conn=256`).
- Feature flags — `crates/gw-proxy/Cargo.toml`: `default = []`, `tunnel = ["dep:gw-tunnel-client"]`. `crates/gw-gateway/Cargo.toml`: `default = []`, `tunnel = ["dep:gw-tunnel-client", "gw-proxy/tunnel"]`.

## Deliberate behaviours
- Tunnel is opt-in twice over: it requires both the `tunnel` Cargo feature at build time and `cfg.tunnel.enabled = true` at boot. With either off, `pick_peer` sees `tunnel = None` (or the `not(feature)` arm) and produces a byte-identical Direct `HttpPeer` — the comments in `crates/gw-proxy/src/filters/upstream.rs` and `crates/gw-gateway/src/lib.rs` call this the non-breaking-on-rollout guarantee.
- `require_tunnel = true` is a hard constraint: when resolution is `Direct`, the rustls branch in `crates/gw-proxy/src/filters/upstream.rs` returns `GW_TUNNEL_NO_NODE` rather than falling back to Direct (ADR-T-4, enforced by the `tunnel_require_means_hard_fail` invariant).
- Tunnel and impersonate are mutually exclusive: a vendor whose `egress_mode = Impersonate` that also resolves to `Use(_)` is failed with `GW_TUNNEL_IMPERSONATE_CONFLICT` (503) instead of silently picking one path (`crates/gw-proxy/src/filters/upstream.rs`).
- Anti-SSRF is fail-closed: `SafeDnsResolver::resolve` returns `BlockedIpError` if any resolved IP is in the blocklist and does not try a different IP (`crates/gw-tunnel-client/src/safe_dns.rs`); `assert_target_allowed` defaults to deny and only permits explicit `(host, port)` pairs (`crates/gw-tunnel-client/src/target_filter.rs`).
- Cold-start nodes fail soft into retry: `peer_for_node` returns `NoLive` when a freshly-spawned transport has not completed its handshake; the rustls branch pushes the key onto `ctx.retry_blacklist` before emitting `GW_TUNNEL_NO_LIVE`, so a request retry lands on a different key (`crates/gw-proxy/src/filters/upstream.rs`, `crates/gw-proxy/src/tunnel_stack.rs`).
- Decode is memory-bounded: frames whose declared length exceeds `MAX_PAYLOAD_LEN` are rejected at decode (`crates/gw-tunnel-client/src/frame.rs`).
- Node list reloads are atomic: `peer_for_node` takes one `nodes.load_full()` snapshot for the whole method so a concurrent `reload_nodes` cannot make its two node-lookup sites disagree (`crates/gw-proxy/src/tunnel_stack.rs`).

## Cross-process touchpoints
- Remote proxy node (aether-hub): the frame byte layout in `crates/gw-tunnel-client/src/frame.rs` is declared to match `aether-hub/src/protocol.rs`; `WsTransport` dials the node's `ws[s]://host:port/path` and the real upstream target is sent as an `Open` frame payload.
- DoH provider: `SafeDnsResolver::cloudflare_default()` resolves over Cloudflare DoH (`1.1.1.1`/`1.0.0.1`) via hickory (`crates/gw-tunnel-client/src/safe_dns.rs`).
- Datastore: proxy nodes come from `EntityStore::proxy_nodes_list_or_load()` (migration `0005_proxy_nodes.sql`), mapped `ProxyNode → ProxyNodeView` at boot and on the 5s refresh poll (`crates/gw-gateway/src/lib.rs`); `VendorKey.tunnel_preference` rides the vendor-key entity.
- Admin/health: `TunnelStack::health_snapshot()` and the `#[cfg(feature = "tunnel")]` block in `crates/gw-gateway/src/health.rs` expose per-node `transport_present`.
- Metrics: `gw_tunnel_resolve_total`, `gw_tunnel_open_total`, `gw_tunnel_transport_present`, `gw_target_filter_denied_total`.

## Invariants & lints
- `no_dead_tunnel_use_alias` (`scripts/check-invariants.sh`): the `pub use gw_tunnel_client` re-export count in `crates/gw-gateway/src/` and the `TunnelStack` mention count in `crates/gw-proxy/src/` must both be zero or both be nonzero — the re-export and the consumer move together.
- `tunnel_require_means_hard_fail` (`scripts/check-invariants.sh`): every `require_tunnel` source line in `crates/` must have a `GW_TUNNEL_NO_NODE` within the next 8 lines, forbidding a silent Direct fallback when a tunnel is required.
- `no_double_rustls` (`scripts/check-invariants.sh`): `Cargo.lock` may hold exactly one `rustls` version, so the tunnel WS TLS stack does not introduce a second rustls (the gateway already installs a single ring provider; see `crates/gw-gateway/Cargo.toml`).
- `crate_layering` (`scripts/check-invariants.sh`): `gw-tunnel-client` is business-layer and must not depend on the execution layer; `gw-capability` must not depend on `gw-tunnel-client`.

## Not built → ROADMAP
- Tunnel is absent from the shipped binary. Both `crates/gw-proxy/Cargo.toml` and `crates/gw-gateway/Cargo.toml` set `default = []`, and the release build `cargo build --release --locked -p gw-gateway` in `.gitlab-ci.yml` does not pass `--features tunnel`; only the `#[cfg(not(feature = "tunnel"))]` Direct arm of `crates/gw-proxy/src/filters/upstream.rs` is compiled. Decide whether to enable `tunnel` by default (and add the build flag to CI) or keep it an explicit opt-in.
- RUNTIME-RISK: in the default (non-tunnel) build, the `require_tunnel = true` hard-fail does not exist — the `not(feature)` arm of `crates/gw-proxy/src/filters/upstream.rs` always produces a Direct `HttpPeer`, so a `VendorKey` carrying `tunnel_preference.require_tunnel = true` silently egresses Direct. The `GW_TUNNEL_NO_NODE` guard only compiles under `#[cfg(feature = "tunnel")]`. If such keys can be configured, the shipped artifact violates their intent.
- The end-to-end tunnel test does not run in the normal suite. `crates/gw-gateway/tests/e2e_tunnel.rs` is `#![cfg(feature = "tunnel")]` and both `#[tokio::test]`s carry `#[ignore = "requires Docker (testcontainers Redis + Postgres); full pingora round-trip is v2 scope"]`; the file header notes the full Pingora → node → upstream round-trip is deferred and `peer_for_node`'s live-WS path is not exercised. Enable it (run `--features tunnel --test e2e_tunnel -- --ignored`) and extend it past `TunnelStack::resolve` to a real frame round-trip.
- `GW_TUNNEL_DNS_BLOCKED` is declared in `crates/gw-core/src/error/codes.rs` but no source under `crates/gw-proxy/` or `crates/gw-gateway/` emits it; `SafeDnsResolver` is constructed at boot and held by `TunnelStack` but is not consulted on the `peer_for_node` path. Wire DoH pre-resolution into the tunnel open path so the code can be emitted, or drop the unused code.
- `TunnelNodeHealth::last_pong_age_secs` is always `None` (`crates/gw-proxy/src/tunnel_stack.rs`); the per-node pong age is not surfaced to the health snapshot even though `WsTransport::last_pong_age` exists. Thread the live transport's pong age through `health_snapshot`.
- `ProxyNode.auth_token_enc` is carried on the entity but never decrypted or sent: the frame protocol defines `MsgType::ControlAuth`, yet no source builds or sends an auth frame, so nodes are dialed unauthenticated. Implement node-auth handshake using the encrypted token.
