# 09 — Tunnel (as-built)
- Family: tunnel · Backing crates: gw-tunnel-client, gw-tunnel-server · Source-of-truth: `crates/gw-tunnel-client/src/{cnexus,core.rs,target.rs,resolver.rs,safe_dns.rs,target_filter.rs}`, `crates/gw-tunnel-server/src/lib.rs`, `crates/gw-proxy/src/{tunnel_stack,tunnel_bridge}.rs`, `crates/gw-proxy/src/filters/upstream.rs` · Status: owned `ailinkmax-tunnel` server/client, node resolution, safe DNS, target filtering, loopback HTTP bridge, and config boot are default-compiled into the single gateway artifact. Runtime enablement still requires `[tunnel].enabled = true`.

## Purpose
Route selected upstream LLM traffic through a first-party WebSocket tunnel node instead of dialing the provider directly, so egress can originate from a different network location. W8 owns the protocol contract in `docs/spec/10-owned-tunnel-protocol.md`; prior aether/mock behavior is reference material only, not a compatibility target. The decision is per-`VendorKey`: the resolver picks a node (or Direct) from the key's `tunnel_preference` and the operator-configured node list, `TunnelStack::peer_for_node` validates DNS/target/live transport and materialises a Pingora `HttpPeer` pointed at the in-process loopback bridge. The bridge opens an owned tunnel stream to the selected node, sends HTTP/1 bytes as `Data`, and relays response bytes back to Pingora.

## As-built surface
- Cnexus frame codec — `crates/gw-tunnel-client/src/cnexus/frame.rs`: `Frame { msg_type, flags, stream_id, payload }`; `MsgType` (`Open=0x01 … Pong=0x05`, `Error=0x06`, `ControlAuth=0x10`, `ControlNodeInfo=0x11`); `encode_frame` / `decode_frame`; constants `MAGIC=[0xAE,0x21]`, `VERSION=1`, `HEADER_LEN=14`, `MAX_PAYLOAD_LEN=4 MiB`; `FrameError` (BadMagic / BadVersion / UnknownMsgType / PayloadTooLarge). Header layout `magic(2)|version(1)|msg_type(1)|flags(2)|stream_id(4)|length(4)|payload`.
- Cnexus WS transport — `crates/gw-tunnel-client/src/cnexus/transport.rs`: `WsTransport::connect` (tokio-tungstenite) spawns send, recv/router, and heartbeat tasks; `TransportConfig { url, auth_token, heartbeat_interval=30s, missed_pong_threshold=3, max_streams_per_conn=256 }`; when `auth_token` is present it sends a `ControlAuth` frame on stream `0` after the WS split is ready; `is_alive`, `last_pong_age`, compatibility wrappers `send_open` / `send_data`, and `open_stream(target) -> TunnelStream`. Inbound `Data` / `Close` / `Error` is routed by `stream_id`; `TunnelStream::send_data` chunks at `MAX_PAYLOAD_LEN`, `recv` yields data/close/error events, and the stream cap is enforced with permits. Liveness is an `AtomicBool` flipped on send error, stream error, or missed-pong threshold. It also implements `gw_tunnel_client::Transport` for `StreamTarget::Tcp`.
- Cnexus reconnect pool — `crates/gw-tunnel-client/src/cnexus/pool.rs`: `PoolConfig { heartbeat_interval, max_streams_per_conn, backoff_min=1s, backoff_max=60s, backoff_jitter=0.2 }`; `jittered_backoff(attempt, cfg)` = `min*2^attempt` capped at `max` then perturbed `±jitter`; `ReconnectingTransport::start` supervises a `WsTransport` behind an `ArcSwapOption`, recreating it on death with backoff; `current()` returns the live handle or `None` between attempts. It implements `gw_tunnel_client::Transport` by delegating to the current live Cnexus transport.
- Protocol-neutral surface — `crates/gw-tunnel-client/src/core.rs` and `target.rs`: object-safe `Transport` with `open_stream(StreamTarget) -> StreamHandle`, `alive()`, `last_heartbeat_age()`, `tunnel_protocol()`, and `close()`; `TransportError`; boxed bidirectional `StreamHandle`; `StreamTarget` is `#[non_exhaustive]` and currently ships only `Tcp { host, port, tls }`.
- Resolver — `crates/gw-tunnel-client/src/resolver.rs`: `resolve_tunnel(ctx, nodes) -> TunnelResolution::{Use(node_id), Direct}`. Filters nodes by `enabled`, `allowed_provider_ids` containing the provider, and `allowed_vendor_key_ids` (empty = unrestricted); intersects with `preference.preferred_node_ids` when non-empty; empty result ⇒ `Direct`; sorts by `latency_ms` when `prefer_low_latency`. Re-exports `gw_core::entity::TunnelPreference` as `TunnelPreference`. `ProxyNodeView` mirrors the entity (`id, ws_url, auth_token, enabled, latency_ms, allowed_provider_ids, allowed_vendor_key_ids, tunnel_protocol`).
- Safe DNS — `crates/gw-tunnel-client/src/safe_dns.rs`: `is_ip_blocked` (private/loopback/link-local/broadcast/documentation/unspecified/CGNAT 100.64/8 for v4; loopback/unspecified/ULA fc00::/7/link-local fe80::/10 for v6); `BlockedIpError`; `SafeDnsResolver::cloudflare_default()` (hickory DoH over Cloudflare HTTPS) with a TTL+capacity LRU cache (`cache_ttl=600s`, `cache_cap=4096`); `resolve` order = override map → cache → DoH, post-filtering every IP through `is_ip_blocked` and returning `Err` on any blocked IP (no fall-through to another IP); `set_override` + `OverrideGuard` (test-only override/restore). Gateway boot may populate the override map from `[tunnel].dns_overrides`; production default is empty, and config validation rejects blocked/private override IPs.
- Target whitelist — `crates/gw-tunnel-client/src/target_filter.rs`: process-global, default-deny `(host, port)` whitelist (`ArcSwap`); `set_whitelist`, `assert_target_allowed(url) -> Result<(), TargetDenied>` (ticks `gw_target_filter_denied_total`), `ResetGuard` for tests.
- Owned server — `crates/gw-tunnel-server/src/lib.rs`: first-party WebSocket acceptor for `ailinkmax-tunnel`. Optional `ControlAuth` is required as the first client frame when configured; the server sends `ControlNodeInfo`, validates `Open host:port`, applies target allow-list/private-IP policy, enforces `max_streams_per_conn`, relays TCP bytes as bidirectional `Data`, and releases stream state on `Close`, `Error`, EOF, or socket failure. The binary entrypoint is `gw-tunnel-server`.
- Owned server egress proxy — `gw-tunnel-server` can dial upstream targets through a deployment-level SOCKS5 proxy with `--proxy-url socks5[h]://[user:pass@]host:port` or the fallback `PROXY_URL` environment variable. Missing or empty config keeps direct egress. `socks5` resolves target DNS locally and sends the resolved IP to the proxy; `socks5h` sends the hostname to the proxy so DNS happens at the proxy. Userinfo is percent-decoded before SOCKS5 auth. The proxy host is resolved at dial time, not parse time, so proxy container IP changes do not stale-cache the address.
- Decision stack — `crates/gw-proxy/src/tunnel_stack.rs`: `TunnelStack` owns a `DashMap<node_id, Arc<ReconnectingTransport>>` (created lazily), an `ArcSwap<Vec<ProxyNodeView>>`, an `Arc<SafeDnsResolver>`, the `PoolConfig`, a `TransportConfig` template, and the bridge loopback address. `resolve(provider_id, key_id, pref)` delegates to `resolve_tunnel` over the live snapshot. `peer_for_node(node_id, host, port)` pre-resolves the upstream host through `SafeDnsResolver` (`DnsBlocked` on blocked/private IP), takes one node snapshot, lazily spawns the node's `ReconnectingTransport` with the node `auth_token`, returns `TunnelPeerError::NoLive` when `current()` is `None`, runs the upstream `host:port` through `assert_target_allowed` (`TargetDenied` on reject), and otherwise builds an `HttpPeer` pointed at the loopback bridge, not the node WebSocket endpoint. `reload_nodes` wholesale-swaps the snapshot; `start_probe_loop(interval, shutdown_token)` emits `gw_tunnel_transport_present` and `gw_tunnel_last_pong_age_seconds`. **Probe loop is shutdown-aware.** `start_probe_loop` takes a `ShutdownToken` and exits cleanly on cancellation via `tokio::select!`. The bootstrap registers the returned `JoinHandle` with `ShutdownCoordinator` so drain awaits the probe loop's exit before terminating the runtime; `health_snapshot()` feeds the tunnel health endpoint with `transport_present` and live `last_pong_age_secs`.
- Bridge — `crates/gw-proxy/src/tunnel_bridge.rs`: loopback HTTP/1 server used by the default-compiled tunnel path. It reads internal headers `X-Gateway-Tunnel-Node-Id`, `X-Gateway-Tunnel-Target`, and `X-Gateway-Tunnel-Target-Tls`, strips all `X-Gateway-Tunnel-*` headers before forwarding, opens `WsTransport::open_stream(target)`, sends a rendered HTTP/1 request as opaque `Data`, optionally owns TLS for HTTPS targets, and streams inbound bytes back as the upstream response. Missing metadata, no live node, tunnel `Error`, or premature `Close` map to gateway-visible 5xx responses.
- Upstream wiring — `crates/gw-proxy/src/filters/upstream.rs`: the filter resolves `(tunnel_resolution, tunnel_require)` once from `picked_arc.tunnel_preference` (defaulting to `TunnelPreference::default()`) by calling `TunnelStack::resolve` when a stack is present; with no stack it resolves to `Direct`. The impersonate branch bails with `GW_TUNNEL_IMPERSONATE_CONFLICT` (503) if resolution is `Use(_)`; the rustls branch maps `Direct`+`require_tunnel` → `GW_TUNNEL_NO_NODE` (502), `Direct` → Direct `HttpPeer`, `Use(node_id)` → `peer_for_node` (errors mapped to `GW_TUNNEL_NO_LIVE` 502 / `GW_TUNNEL_DNS_BLOCKED` 502 / `GW_TUNNEL_TARGET_DENIED` 502). On `Use`, `ReqCtx` stores selected node/target/TLS ownership metadata; `rewrite_request` injects the three internal bridge headers after archiving so they are not persisted, and the bridge strips them before opening the tunnel stream.
- Entities — `crates/gw-core/src/entity.rs`: `TunnelPreference { preferred_node_ids, require_tunnel, prefer_low_latency }` (lives in `gw-core` because `VendorKey` embeds it); `VendorKey.tunnel_preference: Option<TunnelPreference>`; `ProxyNode { id, ws_url, enabled, latency_ms, allowed_provider_ids, allowed_vendor_key_ids, tunnel_protocol, auth_token_enc }`. `ProxyNode.tunnel_protocol: TunnelProtocol` defaults to `Cnexus`; migration `0011_proxy_nodes_protocol.sql` backfills the JSONB payload key for existing rows.
- Error codes — `crates/gw-core/src/error/codes.rs`: `GW_TUNNEL_NO_NODE`, `GW_TUNNEL_NO_LIVE`, `GW_TUNNEL_TARGET_DENIED`, `GW_TUNNEL_DNS_BLOCKED`, `GW_TUNNEL_IMPERSONATE_CONFLICT` (lines 106–112).
- Boot wiring — `crates/gw-gateway/src/lib.rs`: `pub use gw_tunnel_client`; when `cfg.tunnel.enabled` is true the boot path parses `tunnel.target_whitelist` into `set_whitelist`, applies `tunnel.dns_overrides` via `safe_dns::set_override`, builds `PoolConfig`/`TransportConfig`/`SafeDnsResolver::cloudflare_default()`, decrypts `ProxyNode.auth_token_enc` into `ProxyNodeView.auth_token`, loads `proxy_nodes_list_or_load()` into `ProxyNodeView`s, starts the loopback bridge, constructs the `TunnelStack` with the bridge address, spawns a 5s polling node-refresh task, and calls `start_probe_loop(Duration, ShutdownToken)` — the returned `JoinHandle` is registered with `ShutdownCoordinator`; nodes with undecryptable auth tokens are dropped during refresh. When false it logs and yields `None`. Config struct keys come from `config/default.toml` `[tunnel]` (`enabled=false`, `doh="cloudflare"`, `dns_cache_ttl_secs=600`, `target_whitelist=[]`, `dns_overrides={}`, `heartbeat_interval_secs=30`, `missed_pong_threshold=3`, `backoff_min_secs=1`, `backoff_max_secs=60`, `max_streams_per_conn=256`).
- Feature flags — tunnel no longer has a Cargo feature. `gw-tunnel-client`, `tokio-rustls`, and `webpki-roots` are default-visible dependencies where used.
- CI artifacts — `.gitlab-ci.yml`: `rust-build` / `push-image` build and publish the single gateway artifact tagged with the commit SHA and `latest` on the default branch. `docs/design/2026-06-15-tunnel-default-compile-decision.md` records the artifact policy change.

## Deliberate behaviours
- Tunnel data path is runtime opt-in: it requires `cfg.tunnel.enabled = true` at boot. With it off and no key requiring a tunnel, `pick_peer` sees `tunnel = None` and produces a byte-identical Direct `HttpPeer`.
- `require_tunnel = true` is a hard constraint: when resolution is `Direct`, `crates/gw-proxy/src/filters/upstream.rs` returns `GW_TUNNEL_NO_NODE` rather than falling back to Direct (ADR-T-4, enforced by the `tunnel_require_means_hard_fail` invariant).
- Tunnel and impersonate are mutually exclusive: a vendor whose `egress_mode = Impersonate` that also resolves to `Use(_)` is failed with `GW_TUNNEL_IMPERSONATE_CONFLICT` (503) instead of silently picking one path (`crates/gw-proxy/src/filters/upstream.rs`).
- Anti-SSRF is fail-closed: `SafeDnsResolver::resolve` returns `BlockedIpError` if any resolved IP is in the blocklist and does not try a different IP (`crates/gw-tunnel-client/src/safe_dns.rs`); `assert_target_allowed` defaults to deny and only permits explicit `(host, port)` pairs (`crates/gw-tunnel-client/src/target_filter.rs`).
- Cold-start nodes fail soft into retry: `peer_for_node` returns `NoLive` when a freshly-spawned transport has not completed its handshake; the rustls branch pushes the key onto `ctx.retry_blacklist` before emitting `GW_TUNNEL_NO_LIVE`, so a request retry lands on a different key (`crates/gw-proxy/src/filters/upstream.rs`, `crates/gw-proxy/src/tunnel_stack.rs`).
- Decode is memory-bounded: frames whose declared length exceeds `MAX_PAYLOAD_LEN` are rejected at decode (`crates/gw-tunnel-client/src/cnexus/frame.rs`).
- Node list reloads are atomic: `peer_for_node` takes one `nodes.load_full()` snapshot for the whole method so a concurrent `reload_nodes` cannot make its two node-lookup sites disagree (`crates/gw-proxy/src/tunnel_stack.rs`).
- Tunnel code is part of the default artifact. `[tunnel].enabled = false` remains the operator-selected off state.
- `gw-tunnel-server` SOCKS5 egress is a node deployment setting. The gateway database may record a node `proxy_url` for operator visibility, but the server process only uses its own `--proxy-url` / `PROXY_URL` value. This matches the migration contract: an Aether-era node using `proxy_url = socks5://proxy:1080` can be replaced by a Cnexus `gw-tunnel-server` deployment launched with the same `--proxy-url`.

## Cross-process touchpoints
- Remote proxy node: the compatibility target is the first-party `gw-tunnel-server` speaking `ailinkmax-tunnel` as specified in `docs/spec/10-owned-tunnel-protocol.md`. Aether and prior mocks remain reference material only.
- Egress proxy: optional SOCKS5/SOCKS5h service reachable from the `gw-tunnel-server` process. Startup probes warn only; they never refuse listener bind, because deployers may stage the proxy separately.
- DoH provider: `SafeDnsResolver::cloudflare_default()` resolves over Cloudflare DoH (`1.1.1.1`/`1.0.0.1`) via hickory (`crates/gw-tunnel-client/src/safe_dns.rs`).
- Datastore: proxy nodes come from `EntityStore::proxy_nodes_list_or_load()` (migration `0005_proxy_nodes.sql`), mapped `ProxyNode → ProxyNodeView` at boot and on the 5s refresh poll (`crates/gw-gateway/src/lib.rs`); `VendorKey.tunnel_preference` rides the vendor-key entity.
- Node auth: `ProxyNode.auth_token_enc` is decrypted by `crates/gw-gateway/src/lib.rs` with the gateway KEK and passed as `ProxyNodeView.auth_token`; `crates/gw-tunnel-client/src/cnexus/transport.rs` sends it as a `ControlAuth` frame when present.
- Admin/health: `TunnelStack::health_snapshot()` and `crates/gw-gateway/src/health.rs` expose per-node `transport_present` and `last_pong_age_seconds`.
- Metrics: `gw_tunnel_resolve_total`, `gw_tunnel_open_total`, `gw_tunnel_transport_present`, `gw_tunnel_last_pong_age_seconds`, `gw_tunnel_reconnect_total`, `gw_tunnel_doh_resolve_total`, `gw_target_filter_denied_total`.

## Invariants & lints
- `no_dead_tunnel_use_alias` (`scripts/check-invariants.sh`): the `pub use gw_tunnel_client` re-export count in `crates/gw-gateway/src/` and the `TunnelStack` mention count in `crates/gw-proxy/src/` must both be zero or both be nonzero — the re-export and the consumer move together.
- `tunnel_require_means_hard_fail` (`scripts/check-invariants.sh`): every `require_tunnel` source line in `crates/` must have a `GW_TUNNEL_NO_NODE` within the next 8 lines, forbidding a silent Direct fallback when a tunnel is required.
- `no_double_rustls` (`scripts/check-invariants.sh`): `Cargo.lock` may hold exactly one `rustls` version, so the tunnel WS TLS stack does not introduce a second rustls (the gateway already installs a single ring provider; see `crates/gw-gateway/Cargo.toml`).
- `crate_layering` (`scripts/check-invariants.sh`): `gw-tunnel-client` is business-layer and must not depend on the execution layer; `gw-capability` must not depend on `gw-tunnel-client`.

## Per-node protocol discriminator (Phase 1, 2026-06-15)

`ProxyNode.tunnel_protocol: TunnelProtocol` records the wire-protocol label a proxy node claims. The serde wire values are `"cnexus"` and `"aether"`; missing payload keys default to `Cnexus` so rows written before migration `0011_proxy_nodes_protocol.sql` continue to deserialize. Runtime behavior in this branch is Cnexus-only. The `"aether"` label is retained for stored-data compatibility and operator visibility, but original Aether-node compatibility is not built.

`gw-tunnel-client/src/cnexus/` is bit-compatible with the existing `gw-tunnel-server` wire protocol. The crate root remains reserved for protocol-neutral code: `resolver`, `safe_dns`, `target_filter`, `core.rs`, and `target.rs`.
