# Egress-impersonate — known gaps

Operational follow-ups carried out of the egress-impersonate landing (Phases 1–5 of
[`docs/superpowers/plans/2026-05-28-egress-impersonation.md`](../superpowers/plans/2026-05-28-egress-impersonation.md)).
This file is the operational counterpart of §11 of
[`docs/superpowers/specs/2026-05-28-egress-impersonation-design.md`](../superpowers/specs/2026-05-28-egress-impersonation-design.md);
update it when an item is resolved or a new gap surfaces in production.

| # | Area | Symptom / question | Mitigation in v1 | Resolution path |
|---|------|--------------------|-------------------|-----------------|
| 1 | OpenAI Codex profile headers | The spec uses `OpenAI-Beta: responses=v1` as the static `OpenAI-Beta` value. The real codex-rs source may diverge by the time this lands. | Header set is fail-static, documented capture procedure; `gw_core::impersonate::openai_codex::headers()` uses the spec values and deviations are not auto-detected. | Before enabling the Codex profile for a production tenant, run `scripts/capture_real_client_headers/codex/capture.sh` against a live session and reconcile. Header-drift CI (Task 6.4) makes this routine. |
| 2 | Codex `x-codex-turn-state` TTL | The `TurnStateCache` TTL is set to 300 s based on an educated guess. Real Codex CLI behaviour may rotate the turn state more aggressively or hold it longer. | TTL is configurable via `[egress].turn_state_ttl_secs`; default 300 s; fail-static, documented capture procedure. | Run Stage 1 with packet capture against a real Codex CLI session and tune the default. |
| 3 | Gemini CLI profile choice | The Gemini CLI in the wild is Node + undici, not Chrome. We picked the Chrome 131 profile because it has the highest empirical pass-through rate against Google's edge. The fingerprint is therefore "over-impersonated". | Single `GeminiCli` profile shipped; over-impersonation is the conservative direction. | If Google starts blocking Chrome-class fingerprints on Gemini CLI traffic, add a second `GeminiNodeUndici` profile and let admins pick per vendor. Metric to watch: 401/403 ratio on Gemini vendors after Stage 1. |
| 4 | `wreq` version policy | `wreq` and `wreq-util` follow upstream Chrome version drift; pinning vs floating both have costs. Floating risks silent fingerprint changes; pinning rots the impersonation. | v1 pins `wreq = 6.0.0-rc.28`, `wreq-util = 3.0.0-rc.11`. Header-drift CI checks application headers only and cannot catch TLS / HTTP-2 fingerprint drift. | Re-evaluate quarterly. The early warning for the pinned `wreq` / `wreq-util` pair is `crates/gw-egress-impersonate/tests/self_fingerprint.rs`; a `wreq` bump that shifts ClientHello fails that test, then maintainers decide whether to accept the bump or patch the local profile pool. |
| 5 | CLI client version pool refresh | Static client-version constants (Claude Code, Codex, Gemini CLI) embedded in the profile pools go stale as those CLIs ship new releases. | Initial pools were captured at landing time; manual refresh only. `.github/workflows/header-drift.yml` (Task 6.4) reminds maintainers when the public CLI version moves. | Phase 7: evaluate an auto-PR bot that diffs the upstream CLI releases against `crates/gw-core/src/impersonate/profile/*.rs` and opens PRs. |
| 6 | Performance SLO | The `loopback_rtt_seconds` p99 SLO is 200 µs (UDS). If we exceed it, where does the regression go first? | Metric is exported; no automatic action on breach. The Phase-6 microbench (Task 6.2) establishes the baseline. | A sustained breach triggers an issue. Options in order of preference: `ClientPool` cache tuning, `hyper` keep-alive tuning, profile bind sharding, reverting that specific vendor to direct egress. Reverting to "Approach A" (rustls + custom fingerprint) is the last resort. |
| 7 | `identity_snapshot` admin overrides | If an operator hand-edits the `identity_snapshot` JSON column, should the lazy-persist path overwrite it on the next request? | v1 rule: lazy-persist only fires when the column is `IS NULL`; non-null values are trusted as-is. | Admin UI must expose an explicit "regenerate identity" action that NULLs the column, so the next request reseeds it deterministically. Until that ships, ops must clear the column by hand. |
| 8 | Tunnel ↔ impersonate mutual exclusion | `pick_peer` enforces "a vendor cannot both tunnel and impersonate" at request time via `GW_TUNNEL_IMPERSONATE_CONFLICT`. The admin-update path does not check this. | Runtime fail-closed is acceptable — the conflict cannot send a packet to the wrong place. | A future `gw-store` vendor-update validator should reject the combination at write time so it never reaches a request. Lives next to the existing `target_whitelist` validation on `Vendor`. |
| 9 | `identity_snapshot` loader read path | `PgSnapshotWriter` writes to the dedicated `vendor_keys.identity_snapshot` column (migration 0009), but the original `VENDOR_KEY_SQL` only selected `payload, version` and `VendorKeyRow` looked for the snapshot inside `payload.identity_snapshot`. The persisted column was therefore never surfaced to `VendorKey.identity_snapshot`, so every cold load re-derived from RNG and any future `wreq` bump would silently shift the fingerprint of "persisted" keys. | Implementation handoff: `VENDOR_KEY_SQL` now folds the column into payload via `jsonb_set(payload, '{identity_snapshot}', COALESCE(identity_snapshot, 'null'::jsonb), true)`, mirroring the `signature_secret` trick in `API_KEY_SQL`. Guarded by `e2e_impersonate::identity_snapshot_round_trips_through_postgres` (Task 6.1b), which seeds a key, persists via the real queue, then re-loads through a fresh `EntityStore` (cold L1/L2) and asserts the upstream User-Agent is identical across both requests. | None pending. If the loader ever stops folding the column, the round-trip test fails before the regression reaches production. |
| 10 | macOS bench: TCP loopback ephemeral-port exhaustion | `cargo bench -p gw-egress-impersonate --bench loopback_rtt` panics on Darwin with `Os { code: 49, AddrNotAvailable }` after the UDS group completes. 50 k rapid TCP connect/close cycles exhaust the 16 k ephemeral-port range left by macOS's default `net.inet.ip.portrange.first/last`. UDS (the default `gw-proxy` egress transport) measured 201–203 µs p99, within SLO (Gap #6). | The TCP path is exercised by E2E and unit tests, not the bench; UDS is what production runs. Bench panic is environmental, not a regression. | Run the bench on Linux CI (default ephemeral range ≈ 28 k–60 k). For local Darwin runs, widen the port range via `sudo sysctl -w net.inet.ip.portrange.first=10000`. |
